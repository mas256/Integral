# 文書作成規格 第3版 工程1:要件定義

この工程の目的は、依頼者が何を書きたく、誰に何を伝えたく、どう伝えたいかを、草案を作れる水準まで議論で確定することである。本文も草案も、この工程では書かない(W2.5の場合を除く)。

## R1 始め方

- R1.1 資料(既存原稿、メモ、壁打ちメモ、参考文書、author-style.md、文体の見本)が渡された場合は、先に読む。読めなかった箇所は報告する。壁打ちメモ(Z4.1)の論点のうち、依頼者の反応が「採る」のものは言い直しに含め、「保留」「未確認」のものは質問にする。AIの案は、依頼者が採用を明示するまで要件に入れない(W1.1)。
- R1.2 最初の発言は、次の3つを、この順に書く。
  1. 言い直し:依頼文と資料から読み取れた範囲で、要件定義書の書式(R4.1)を埋めたもの。読み取れない項目は「未定」と書き、推定で埋めない。
  2. 読み取りに自信のない項目:依頼者の言葉からではなく、資料の様子から読み取った項目を挙げる。
  3. 質問:R2.1の表で基準を満たしていない項目について尋ねる。必須の2項目(R2.2)が未定なら、それを先頭に置く。
- R1.3 依頼者が書きたい内容をまだ言葉にできていない場合は、選択肢を並べる前に、依頼者自身の言葉を引き出す問いを使う(どんな読者のどんな場面を思い浮かべているか、読み終えた読者にどうなってほしいか、書こうと思ったきっかけは何か)。

## R2 確定する事項

- R2.1 次の表の各項目を、基準を満たすまで議論する。基準を満たした項目は、それ以上尋ねない。

| 項目 | 確定したと言える基準 | 未定のときの問い方 |
| --- | --- | --- |
| 主題と範囲 | 扱うことと扱わないことが、具体的な事柄の名前で挙がっている。主題に隣り合う話題のそれぞれについて、入るか入らないかが決まっている | 隣り合う話題を挙げ、一つずつ「これには触れますか」と尋ねる |
| 想定読者と前提知識【必須】 | 読者が誰か(立場、学年、職務など)が書かれている。主題の主要な語のそれぞれについて、説明なしに使ってよいかが決まっている | 主題の主要な語を挙げ、一つずつ「この語は説明なしに使えますか」と尋ねる |
| 読後に期待すること【必須】 | 「読者が〜できる」「読者が〜と分かる」の形の一文になっている。読んだ人に確かめられる形である(問題が解ける、判断が下せる、人に説明できる、など) | 「読み終えた読者に何をしてもらえたら、この文書は成功ですか」と尋ねる |
| 全体を貫く問いまたは主張 | 一文で書ける。文書の各部分が、その問いに答える一部になる | 「この文書が答える問いを一つ挙げるなら何ですか」と尋ねる |
| 必ず入れる論点・題材・例 | 論点ごとに、読後に期待することのどの部分に効くかを言える | 効く先を言えない論点は、R2.3の3で扱う |
| 素材 | 使う資料・既存原稿・データが挙がり、渡されている | 挙がったが渡されていない素材を尋ねる |
| 文書の種類と読まれ方 | 通読する/必要な箇所を引く/判断の材料にする、のどれかが決まっている | 読者がこの文書を開く場面を尋ねる |
| 使用場面・媒体・形式・分量 | 媒体(紙、画面、スライドなど)、ファイルの形式、分量の目安(幅でよい)が決まっている | 決まっていない事項だけを尋ねる |
| 文体と書き方 | author-style がある、または「定めない」と決まっている(R3) | R3に従う |
| 維持すべき内容・書式・制約 | あるか、ないかが決まっている | 既存原稿がある場合に、変えてはいけない箇所を尋ねる |

- R2.2 「想定読者と前提知識」と「読後に期待すること」は必須とする。この2つが確定しないうちは、承認を求めない。読者の出発点と到達点であり、飛躍と負担はこの2つがないと判断できないからである。
- R2.3 依頼者の構想を、W5.3に従って批評する。確かめる観点は次の4つ。
  1. 読後に期待することが、主題の範囲で達成できるか。
  2. 想定読者の前提知識と主題の間を埋める内容が、範囲に入っているか。
  3. 必ず入れたい論点のうち、読後に期待することに結び付かないものがないか。ある場合は、脇道として置くか、目的の方を広げるか、外すかを依頼者に尋ねる。
  4. 範囲が、分量・媒体に対して過大でないか。
- R2.4 主題についてのAIの知識で、依頼者が挙げていない論点を要件に加えない。有用と考える論点は、AI提案として示し、採否を尋ねる(W1.1)。

## R3 author-style の確定

- R3.1 author-style は、handoff.md の N4 に従って確かめる。渡されたものに未記入の欄がなければ、尋ねない。
- R3.2 未記入の欄がある場合と、何も渡されていない場合は、author-style-template.md の問いに沿って尋ねる(N4.4)。依頼者が既に定めを示している事項(依頼文など)は尋ねず、その定めを欄に書く。
- R3.3 新しく作る場合は、style-presets.md の型のうち文書の種類に近いものを、答えの候補として示してよい。型のまま使うか、事項ごとに変えるかは、依頼者が決める。どの型にも近くない文書(物語、随筆、スライドなど)では、型を示さない。
- R3.4 両立しない定めを、両方とも残さない(例:「言い換えを多用する」と「簡潔に書き、重複を削る」)。食い違いに気づいた場合は、どちらにするかを尋ねる。
- R3.5 第3部(用語・表記表)は、この工程では表記の決めのうち決められるものを決める。固定する用語は、工程2で書き加える(O3.4)。
- R3.6 第4部(文体の見本)に見本が挙がった場合は、語尾・語彙に加え、着眼点、問いかけ、説明の詳しさ、文の間合いを読み取り、何の見本かを一行で添える。読み取った特徴を依頼者に示して確かめる。
- R3.7 記入した author-style は、要件定義書とともに示して承認を求める(N4.4の8)。

## R4 要件定義書

- R4.1 handoff.md の N5.1 の書式(依頼内容ファイル)で書く。第1〜11項を埋め、第12項(レビューの指定)は「なし」と書く。該当のない項目は「なし」と書く。依頼者の言葉をできる限りそのまま使い、AIの言い換えで意味を広げない。置き場所は N5.4 に従う(records/brief.md)。
- R4.2 承認を求める前に、次の3つを確かめる。必須の2項目がR2.1の基準を満たしている。「未決事項」に争点が残っていない。AI提案のうち採用されていないものが、要件に入っていない。
- R4.3 要件定義書を示して承認を求める。承認を得たら、工程2へ進む。
