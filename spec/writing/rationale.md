## 3. 設計上の決定(第1版から)

| 決定 | 理由 | 依頼者の承認 |
| --- | --- | --- |
| 対象はあらゆる文書。文体は固定せず、工程1で文書ごとに決める(R3、Y) | 著者規則(講義型)と「文書の書き方」(実務型)は、反復・一文・文体で両立しない。どちらかを固定すると、もう一方の文書が書けない | 済(2026-11-10) |
| core+工程別ファイルに分け、1つのAIが工程ごとに読む(W2) | 工程に関係しない規則を読ませない | 済(2026-11-10) |
| 執筆後の評価を持たない。自己評価も書かせない(M5.3)。規則への適合の点検だけを行う(M4) | 評価はレビュー規格が担う。AIが自分の書いたものを過信するのを防ぐ。点検は照合と検索で確かめられる事項に限る | 評価を持たない点は済(2026-11-10)。点検(M4)も済(2026-11-10) |
| 用語(負担、飛躍、脇道、粒度、争点、判断上の仮定)をレビュー規格と共有する(N1) | 作成とレビューで同じ語が同じ意味になる | 済(2026-11-10) |
| 内容の採否は依頼者だけが決め、AIの案は〔AI提案〕として分ける(W1) | 「思想は書き手にしか作れない」「話題の追加は自分で行う」という方針 | 未確認 |
| 執筆の根拠を、承認済みの成果物に限る(M1.1) | 議論を知るAIは、読者に見えない前提を無意識に補う。単一AIで進める場合の最大の弱点 | 未確認 |
| 一通りに定まる中間過程だけは、執筆者が補ってよい(M1.4) | 式変形の一歩ごとに質問で止まると進まない。選択の余地があるものは補わせない | 未確認 |
| 「言い換え」を、説明の述べ直しと解釈し、用語を変えることは含めない(M3.8、N1.13) | 用語のゆれは読者の負担になる | 済(2026-11-10) |
| 小さい文書は承認を1回にまとめてよい(W2.5) | 連絡文に3回の承認は過剰 | 未確認 |
| 実務型(Y4)は「文書の書き方」からAIが整理した | 出典はです・ます調の解説文で、規則の形になっていない | 未確認 |

## 4. 出典と防ぐ失敗

出典の「第7版」は、文書レビュー規格 第7版のIDである(第8版で一部が共通規格へ移った)。規則IDは第3版のものである。

| 規則 | 出典 | 防ぐ失敗 |
| --- | --- | --- |
| W1 | 文書の書き方 3.1.1(主体は書き手)、依頼者のレビュー方針 | AIが内容を決める、案がいつの間にか要件になる |
| W2.1、W2.3 | 依頼文(議論→草案→執筆) | 要件が固まる前に書き始める、本文と草案が食い違う |

## 5. 取り込まなかったもの

- 文書の書き方 2.5.3(フォント・行間の具体値)と、チェックリスト2の6・8・9(時間・編集・再利用):記録の設計に関する項目で、文書ごとの要件(R2.3)で扱う。
- 文書の書き方の三原則のうち「何度も読み返す」:執筆後の検査に当たるため、レビュー規格に任せた。
- 第7版の採点・ID・台帳・返却の規則:評価のための仕組みであり、作成では使わない。
